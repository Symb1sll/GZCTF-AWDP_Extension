# 测试与部署验收

自动化测试用于检查组件行为，目标环境验收用于确认部署、攻击实例、补丁判题和计分链路。两者不能相互替代。

## 1. 本地自动化测试

在本仓库根目录执行，使用 Python 3.8 或以上版本：

```bash
python3 -B tools/test_apply_overlay.py
python3 -B tools/test_stage_files.py
python3 -B tools/test_production_prepare.py
python3 -B awdp/runner/test_runner.py
python3 -B challenges/ticket-attachments/tools/build_release.py
```

- 覆盖层安装器测试：摘要校验、版本拒绝、已有文件保护、重复应用及文档安装。
- 私有暂存测试：完整发布、失败重试、路径限制及已有目录保护。
- 生产准备测试：使用模拟数据检查版本、数据库迁移、Docker 条件和配置保留，不连接正式服务器。
- Runner 测试：补丁路径限制、Checker 结果解析及提交结果绑定。
- 示例题回归：原始漏洞代码、正确修复、无效修复及关闭业务四类场景。

`build_release.py` 会生成参考补丁和 `ticket-player.tar.gz`。只有正确修复应通过；原始漏洞、无效修复和关闭业务均应失败。选手包仅包含源码和选手说明，不应包含 Checker、管理员配置或参考答案。

Windows 环境若没有符号链接创建权限，相关本地场景可能被跳过。必须在 Linux Docker 判题环境补充验证越界符号链接，不能将普通 HTTP 回归当作完整容器验证。

## 2. 基础设施检查

按 [部署说明](DEPLOYMENT.md) 检查 Docker、AppArmor、资源限制、磁盘和端口，再完成独立测试初始化。`awdp/deploy/verify.sh` 检查入口、端口映射、攻击网络、Runner 和数据库状态。

首页 HTTP 200 只证明入口可达，未知路径的前端 HTML fallback 不能作为专门的健康接口。还需检查 Runner 是否 active、Web 是否异常重启，以及目标数据库是否包含迁移 `20260920053850_AddAwdpSubmissionLedger`。

正式接入前使用 `prepare_gzctf_production.py --expected-image-id 已验收镜像ID --check` 完成只读预检。版本标记和迁移表一致不代表自定义 schema 完整兼容，也不替代功能验收。

## 3. 端到端验收

在独立测试比赛中完成以下检查，再在正式接入后验证目标环境：

1. 原有页面、登录、账户、队伍、比赛和附件访问正常。
2. 动态 Flag 攻击实例可以启动和访问，攻击提交及原有计分正常。
3. 正确修复通过，无效修复和关闭业务的补丁失败；异常请求、超时或格式错误不应获得修复分。
4. 同一参赛记录与题目的重复通过不重复叠加修复分，排行榜与提交账本一致。
5. 不同队伍和比赛的提交、结果及计分相互隔离。
6. 判题完成后临时容器清理，测试和正式任务的专属标签不会相互混用。
7. 正常重启后配置、附件、提交状态和分数持久化；任务恢复行为符合预期。

绑定工具只适配工单示例题，并会短暂停止或启动 Web，应在空闲维护窗口使用。其他题目需要独立设计业务与安全用例，并核对镜像白名单、补丁路径和 Runner 的题目适配要求。

## 4. 备份和恢复验证

正式切换前备份数据库、配置、附件及必要的原镜像，保证备份期间的数据一致性，并保存服务器之外的副本。摘要校验只能证明文件完整性；在隔离环境实际恢复并检查数据，才能验证恢复流程。

回退需同时考虑 Web 版本、数据库 schema 和切换后的新增数据，不能只假定换回旧镜像即可恢复。先确定可用恢复点、恢复顺序及可接受的数据损失，再执行恢复。

## 5. 验证边界

- Checker 是针对已定义业务和安全用例的有限回归测试，不是任意补丁安全性的完整证明。
- 容器共享宿主机内核，Web 和 Runner 是可信控制面，不能视为虚拟机级隔离。
- 默认三个并行判题任务是配置限额，不是大规模比赛容量保证。
- 本项目不提供新版 GZCTF、全部数据库版本或跨架构兼容性保证。
- 正式使用前还需评估镜像供应链、依赖、网络策略和容量，并验证异常断电、队列恢复及备份恢复流程。
